# Local setup and database reliability

This guide is the source of truth for running IlmSaathi locally. It is Windows-first, with equivalent macOS/Linux commands.

## Prerequisites

Use exactly Node.js 22.x and npm 10 or newer. Node.js 22 is the repository baseline. For Docker-free development, install MongoDB Community Server 7 or 8; `mongosh` is not required. Docker development requires a current Docker Desktop with Compose v2.

Verify the native prerequisites:

```powershell
node --version
npm --version
Get-ChildItem 'C:\Program Files\MongoDB\Server' -ErrorAction SilentlyContinue
```

Only when using Docker mode, also verify:

```powershell
docker --version
docker compose version
docker info
```

If docker info fails, Docker Desktop is installed but its engine is not ready. Start Docker Desktop and wait for it to report that the engine is running.

## Recommended on this Windows machine: fully native

Your normal MongoDB Windows service may remain running on port 27017. IlmSaathi starts a separate project-owned MongoDB process on `127.0.0.1:27018`, stores its data under `data/mongodb-native`, and initializes the required single-node replica set (`rs0`) automatically. It does not change the Windows service or require administrator access.

From a fresh PowerShell window:

```powershell
Set-Location C:\Projects\Learning-App
npm ci
npm run env:generate
npm run dev:native
```

`dev:native` starts/validates MongoDB, builds the shared contracts, seeds the subject catalogue idempotently, and starts the API and web app. Open:

- Web: http://localhost:5173
- API liveness: http://localhost:4000/api/health/live
- API readiness: http://localhost:4000/api/health/ready

To run only one application later, use `npm run dev:api` or `npm run dev:web` from the repository root. Both use the same root `.env`; do not run `npm install` inside an individual workspace.

Stop the web and API with `Ctrl+C`. MongoDB intentionally stays available for the next run. Stop it without deleting data when desired:

```powershell
npm run db:native:status
npm run db:native:stop
```

The native database binds only to `127.0.0.1` and intentionally has no local authentication. This is a development convenience, never a production topology.

## Option A: all services in Docker

This is the most reproducible cross-platform path when Docker Desktop is installed because host Node.js and MongoDB versions cannot drift.

```powershell
Set-Location C:\Projects\Learning-App
.\scripts\setup.ps1 -Mode Docker -Start
```

Without -Start, setup validates configuration but does not launch services:

```powershell
.\scripts\setup.ps1 -Mode Docker
docker compose up --wait
```

Useful commands:

```powershell
docker compose ps
docker compose logs --follow --tail=200 mongo api web
docker compose restart api
docker compose down
```

Source files are bind-mounted. Workspace dependencies live in a Docker volume, so Windows and Linux native modules are not mixed.

## Option B: Windows setup wrapper for the fully native path

The PowerShell wrapper performs the same native setup with prerequisite checks. Use this instead of the manual quick start if you prefer a guided command.

```powershell
.\scripts\setup.ps1 -Mode Native -Start
```

Without `-Start`, it installs dependencies and validates configuration, then tells you to run `npm run dev:native`.

On macOS/Linux:

```bash
npm run env:generate
npm ci
npm run dev:native
```

Use `npm ci` for clean setup because this repository commits `package-lock.json`. Use `npm install` only when intentionally adding or updating dependencies.

## Option C: native web/API with MongoDB Atlas

Create .env, replace only MONGODB_URI with the staging/development Atlas SRV connection string, and keep MONGODB_URI_DOCKER for Compose. Use a dedicated non-production database user. Escape reserved characters in credentials or copy the driver URI generated by Atlas.

Then seed and launch the host applications without the native Mongo helper:

```powershell
npm run seed
npm run dev
```

Do not use `npm run dev:native` for Atlas; that command intentionally restores the project-owned local MongoDB URI.

Never put an Atlas connection string in a VITE_ variable, browser code, screenshot, ticket or committed file.

## Environment lifecycle

Generate local credentials once:

```powershell
npm run env:generate
```

The command is idempotent: an existing .env is left untouched. To intentionally rotate every local secret:

```powershell
node scripts/generate-env.mjs --force
```

The old file is backed up as .env.backup-TIMESTAMP and remains ignored by Git.

Important: Mongo's root user is created only when its data volume is first initialized. Rotating MONGO_ROOT_PASSWORD while retaining mongo_data makes the new URI disagree with the stored database credential. Either restore the backed-up .env or intentionally reset the local database.

Destructive local-only reset:

```powershell
# WARNING: permanently deletes the local MongoDB volume and all local data.
docker compose down --volumes
node scripts/generate-env.mjs --force
docker compose up --wait
```

Never run that reset against production infrastructure.

## Connection matrix

| Process location     | Variable used by the API                 | Mongo host                        |
| -------------------- | ---------------------------------------- | --------------------------------- |
| Native host Node.js  | MONGODB_URI from .env                    | 127.0.0.1:27018 project-owned rs0 |
| Atlas host Node.js   | MONGODB_URI from .env                    | Atlas SRV hostname                |
| Codespaces workspace | MONGODB_URI from the dev container       | mongo:27017 private rs0 service   |
| Compose API          | MONGODB_URI_DOCKER mapped to MONGODB_URI | mongo                             |
| Hosted API           | Platform secret MONGODB_URI              | Atlas SRV hostname                |

Do not use localhost from inside the API container; that means the container itself, not MongoDB.

## Readiness sequence

```text
dependency install completes
          |
Mongo replica-set ping succeeds
          |
API connects, indexes initialize, readiness returns 200
          |
web dev server starts and becomes healthy
```

GET /api/health/live proves that the API process is alive. GET /api/health/ready proves it can safely serve database-backed traffic. An API that has lost MongoDB must remain live for orchestration diagnostics but become unready.

## Doctor checks

Run:

```powershell
npm run doctor
```

The doctor validates required files, Node/npm versions, the local environment, secret strength, URI shape, host-vs-container database names, ports, Mongo TCP reachability, and API readiness when the API is running. It never prints secret values.

With `npm run dev:native` running, verify the real database workflow in another PowerShell window:

```powershell
npm run smoke:local
```

This creates a uniquely named temporary educator, exercises registration, onboarding, draft saving and transactional submission, then removes only that smoke-test account and its related records.

For CI/config-only use:

```powershell
node scripts/doctor.mjs --strict --skip-network
```

## Troubleshooting

### MONGODB_URI is empty

Run npm run env:generate. Do not copy a URI into source files.

### Authentication failed after an environment change

For Docker mode, the Mongo volume was likely initialized with the previous root credentials. Restore the matching .env backup. If the data is disposable, use the clearly marked local-only volume reset above. The project-owned native instance on port 27018 intentionally does not use credentials.

### Registration says the Terms or Privacy version is outdated

Restart the API and refresh the registration page. The web app obtains both current versions from `GET /api/v1/auth/csrf`; do not add separate `VITE_TERMS_VERSION` or `VITE_PRIVACY_VERSION` values.

### ECONNREFUSED 127.0.0.1:27018

Run `npm run db:native:start`, then `npm run db:native:status`. The script locates MongoDB Community Server in `C:\Program Files\MongoDB\Server`, initializes rs0 and updates only the host `MONGODB_URI` in `.env`.

### ECONNREFUSED 127.0.0.1:27017 (Docker path)

Run docker compose ps and docker compose logs mongo. For native development, confirm the Mongo port is published. For container development, confirm the API received the Docker URI with host mongo.

### API is live but not ready

Inspect docker compose logs api mongo. Check credential agreement, database network access, initialization/index errors and server-selection timeout. Do not change readiness to return success while disconnected.

### Port already allocated

Stop the conflicting process or change WEB_PORT, API_PORT, MONGO_NATIVE_PORT or MONGO_PORT in .env. Keep WEB_URL, API_URL and CORS_ORIGINS consistent with the new ports.

### Vite proxy reaches localhost from Docker

The container must use API_INTERNAL_URL=http://api:4000. The browser should continue using the relative /api path.

### Docker dependencies are stale

Recreate only the dependency volume, not Mongo data:

```powershell
docker compose down
docker volume ls
```

Confirm the exact IlmSaathi node_modules volume name before removing it. Never use broad volume-prune commands on a machine with other projects.
